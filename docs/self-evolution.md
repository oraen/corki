# 自进化：从工作中学习方法

在管理页主页的“全局配置”中开启“自进化”，或在 `settings.json` 设置：

```json
{
  "features": { "self_evolution": true }
}
```

默认关闭。开启后，Corki 可以将经过验证的方法保存为扩展 Skills，后续任务按现有
Skills 发现和调用机制使用这些方法。这里的“进化”是积累、修正工作方法，不是训练
模型权重，也不是自动修改 Corki 源码。

## 学什么，存在哪里

适合保存的内容包括：复杂任务中验证有效的步骤、可靠的排障流程、成功的替代方案，
以及用户对工作流程和交付质量的纠正。优先修正已有扩展 Skill，再补充相关参考文件，
确有需要才创建新的任务类型 Skill。没有值得长期保留的经验，可以不保存。

新 Skill 位于 `$CORKI_HOME/skills/<name>/SKILL.md`，即管理页的“扩展 Skills”。
未设置 `CORKI_HOME` 时，根目录为 `~/.corki`。内置、公共、项目和插件 Skills 在该
学习工具中只读；需要补充时创建扩展 Skill，不改写其他 Agent 共用的资料。
已禁用的 Skill 不会被学习工具加载、编辑或重新启用。

提示词要求保存通用方法，避免复制凭据、完整日志、会话流水账和无关业务资料。
后台只取有界的展示记录，过滤当前模型密钥及现有秘密识别器可识别的片段；这不是
对任意业务敏感信息的自动识别保证。后台不会额外执行终端命令、联网检索、运行任务
或修改配置。模型仍使用用户已配置的供应商，后台复盘会产生正常模型调用费用。

## 与记忆的关系

自进化和记忆独立，不会强制开启记忆，也不会修改记忆设置。Skills 记录“如何完成某类
任务”；现有记忆系统继续负责其原有职责。即使记忆关闭，也可以学习和使用 Skills。
全局关闭 Skills 时，自进化也不会执行。

## 何时学习

1. 开启状态下，主 Agent 得到独立的学习指引和 `skill_manage` 工具，可以在工作中
   及时保存已经验证的方法。工具提供列表、读取、创建、补丁、资源文件、历史与恢复。
2. 每个持久会话累计完成 10 次模型步骤，或累计完成 10 轮对话后，在成功完成的一轮
   交付之后尝试后台复盘。模型步骤按成功响应的用量事件计数，不把同一事件重复计算。
   成功主动保存 Skill 会重置该会话的计数，避免紧接着再做冗余复盘。
3. 后台使用该轮结束时的模型选择、独立的临时 Agent 及现有模型调用/工具执行循环。
   它只拿到最近至多 100 个展示条目的有界文本证据，不复制隐式推理或原始图片。
   文本预算最多 24K 估算 token，且不超过模型窗口的四分之一。
4. 每次复盘最多 16 次模型请求、120 秒；所有请求的累计估算输入最多为模型原始窗口
   的 75%，且不超过 600K token。达到任意上限即结束，不强迫模型一定生成 Skill。
5. 同一进程、同一 Corki 数据目录的前台任务优先，会取消已有复盘；数据目录级文件锁
   保证不同进程不会同时运行两个复盘。跨进程前台任务不会主动通知另一个进程取消复盘。

取消、失败、手动压缩、临时会话、子 Agent、一次性 EXEC 和定时任务不启动后台复盘。
计数达到阈值时如果有前台任务，暂不启动；计数保留，等待后续成功轮次再检查。
复盘是尽力而为，不是必须完成的用户任务；被取消或失败后不会自动重放有副作用的步骤。

## 开关和运行边界

开关在下一轮开始时决定是否提供学习指引和工具。它只在该功能相关操作中检查文件
签名，文件变化后才解析设置；不会因此在桌面获得焦点或切换历史会话时重载模型配置。
没有后台定时检查。每轮使用开始时取得的开关状态；中途关闭不会打断该轮已经获准的
学习或后台复盘，后续轮次不再学习。工具操作仍检查相关 Skill 的禁用规则；所有写入在
最终提交前检查任务取消状态，保留新任务抢占和退出时的取消保护。
已经提交的修改会保留，关闭开关不会回滚或删除已学习的 Skills，也不会禁止它们按普通
Skills 规则被使用。前台已执行步骤中的学习指引不会从历史上下文中强行删除。

编辑要求先通过学习工具读取具体文件，并提交读取时的内容版本；旧版本修改、目录穿越、
符号链接/目录联接及非扩展技能写入会被拒绝。写入使用文件锁和原子替换，保留已有文件
权限。新 Skill 的目录与 frontmatter 名称一致。写入失败不会覆盖已存在的完整内容。

## 记录和恢复

`$CORKI_HOME/evolution/evolution.sqlite` 独立保存学习计数、复盘状态、失败原因、模型用量
和修改前后的内容。复盘保留最近 200 条，每个技能文件保留最近 20 条修改记录；取消前
已准备但未提交的记录会标记为 `prepared`，不能据此判断文件已经改动。
数据库中的用量属于后台调用，不写入普通会话的回复和用量事件。

开启自进化时，可以让 Agent 用 `skill_manage` 的 `status` 查看记录、`history` 查看
某个扩展 Skill 文件的修改历史，并在读取最新内容后用 `restore` 恢复某条记录的修改前
内容。恢复本身也创建记录。首次创建前没有旧内容，不支持用恢复操作删除新建 Skill。
管理页原有 Skills 编辑、禁用和永久删除功能照常可用；本版本没有新增学习历史页面。

复盘不写入普通会话历史，不出现在最近会话中。异常退出后，下次取得复盘锁会将遗留的
`running` 记录记为 `interrupted`，不推断上一次写入是否成功，也不自动重新执行。

## Hermes 参考与 Corki 取舍

实现参考 Hermes 的 `agent/prompt_builder.py`、`agent/turn_finalizer.py`、
`agent/background_review.py`、`tools/skill_manager_guards.py`、
`tools/skill_manager_tool.py` 和 `tools/skill_ledger.py`：学习类任务方法优先进入 Skill；
交付后复盘；前台优先取消；只读证据与受限写入；读后再写；修改留存可恢复记录；
禁止把未解决失败固化成工具永久不可用。

没有复制 Hermes 的整套 Agent。Corki 复用现有 LangGraphRuntime，以独立模块和提示词
接入；后台使用有界展示证据，没有复制 Hermes 的整段缓存前缀。Hermes 的技能迭代触发
与记忆轮次触发在这里合并为独立学习的 10 步/10 轮阈值。没有接入 Hermes 的记忆写入、
可选技能归档整理、独立辅助模型路由或自动删除技能。这些差异用于保持 Corki 的现有边界。
