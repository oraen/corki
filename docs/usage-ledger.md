# 用量账本

## 生命周期与写入

`usage_events` 是用量分析的事实来源，`usage_threads` 保存会话的渠道、用户、任务与运行批次归属。两表位于 `sessions/corki.db`，没有指向会话内容的外键；归档、物理删除、自动清理、机器人会话重置及定时任务历史清理不会删除已发生的用量。共享一个 SQLite 文件保证事实与模型结果在同一事务提交，无需双文件补偿或后台同步队列。

模型结果插入 `model_steps` 时，数据库触发器同步插入一条事实。唯一的 `step_id` 防止提交重试重复计数，事务回滚也会回滚该事实。分叉会话继承的是上下文观测，不复制实际消耗。既有进程使用原模型结果写入接口也会经过触发器。

`model_steps` 的计数仍用于结果一致性、重放与上下文恢复，不能删除；分析不再读取它。它及其内容仍随会话一起删除。账本没有删除触发器，也不保留提示词、响应、工具结果、原始元数据 JSON、密钥、名称或工作目录。渠道用户归属只保存不透明标识。

## 字段与索引

- `usage_events`：步骤、会话、轮次标识；UTC 时间；供应商、模型；输入、输出、缓存命中、推理、缓存写入计数及上游预算单位。
- `usage_threads`：会话标识、来源类型、可空的渠道/用户/任务/运行标识。即使内容已删除，归属仍保留。
- 表使用 `WITHOUT ROWID`，避免字符串主键的第二份行定位结构。
- 时间表达式索引用于有上下界的时间查询，保持现有 ISO/SQLite 时间格式及本地日期语义。
- 会话与输入/输出计数的覆盖索引用于用户、任务累计消耗。
- 渠道/用户索引及仅覆盖非空值的任务、运行索引用于归属检索。
- 移除原模型恢复表上仅为统计建立的两个索引，不新增重复的日/月汇总表或逐次分析快照。记录线性增长，不自动丢弃历史消耗；大量数据可在有实际测量依据时增加聚合层。

缓存命中属于输入计数的子集，推理也不额外叠加到输入输出总量。展示计数不是费用账单；未返回 usage 的失败请求无法精确推算。首次迁移只能恢复仍存在的模型记录，已经物理删除且无备份的数据不能凭空还原。

## 迁移与归属

初始化时在已有 schema 锁和 SQLite 写事务下安装账本。首次用 SQL 批量投影旧记录，不将响应载入 Python；从已有渠道归属和定时任务运行记录补全历史维度，最后写版本标记。异常会回滚数据与标记，重启可重试；后续启动不再扫描旧记录。

网关和定时任务在模型执行前登记归属，重置会话保留旧归属，新会话另外登记。内存会话继续只在内存中存储，不会因迁移接触用户磁盘目录。本次保持既有已记录模型用量的统计口径，不将缺失的历史或辅助请求估算成实际消耗。

升级前保留 SQLite 在线一致性备份，先在隔离副本验证计数与分类、查询计划、性能和删除行为，再升级正式库。回退优先回退程序：旧程序写入仍受触发器保护。若必须恢复数据库备份，应停写后操作；直接覆盖会丢失备份之后的会话与消耗，不应自动执行。
