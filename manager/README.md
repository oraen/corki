# Corki Manager

本机 H5 管理工作台，默认地址 **http://127.0.0.1:17002**。
前端为 HTML / CSS / JavaScript，配置编辑器使用本地打包的 CodeMirror，无 CDN；后端是 Python
HTTP 服务，复用 Corki 的 JSONC 配置解析器、技能解析器和 MCP 配置校验。
主动点击模型测试时会发起临时模型请求；点击 MCP 测试连接时会初始化服务并读取工具列表。

## 启动

先安装 Corki 开发环境，然后在仓库中运行：

```bash
./manager/bin/start.sh
```

脚本也支持绝对路径，从任意目录运行。使用仓库 `.venv/bin/python`；可通过
`CORKI_MANAGER_PYTHON` 指定已安装 Corki 的 Python。前台运行，Ctrl+C 停止。

Windows PowerShell 使用原生入口，无需 Git Bash 或 WSL：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\manager\bin\start.ps1
```

默认使用仓库 `.venv\Scripts\python.exe`，也可设置 `CORKI_MANAGER_PYTHON` 为已安装
Corki 的 Python 可执行文件完整路径。支持同样的 `--home`、`--workspace`、`--port`
参数；包含空格的路径用引号包围。入口在前台运行，Ctrl+C 停止，启动不修改系统执行策略。

也可在仓库根目录直接使用 Python 入口，不执行任何 `.ps1` 脚本：

```powershell
& .\.venv\Scripts\python.exe -X utf8 -u .\manager\server.py --workspace .
```

```bash
./manager/bin/start.sh --port 17002 --home ~/.corki --workspace /path/to/project
```

只监听 `127.0.0.1`，没有远程登录功能；手机适配指移动宽度布局，不代表已开放
局域网访问。无需改变 Corki 的 provider 配置，管理服务和模型网关分别使用
17002 与 17001 端口。

用户知识库文档保存在 `~/.corki/manager/knowledge/`，内置知识库目录为其中的
`.system/`，内置文档只读。停用状态保存在 `~/.corki/manager/knowledge-state.json`；
知识处理和检索状态以 `~/.corki/knowledge.sqlite` 为准，上述 JSON 保留为管理端兼容状态。

上传文档默认关闭。首次开启使用当前默认供应商与模型执行内置
`corki-text-C&E` Skill，将文章按逻辑分段，保存标题、检索简介、关键词、
原文字符范围、行号和完整段落正文。长文章按有界批次处理，每批可有多个逻辑段；
程序校验全部输入块连续覆盖，并从原文截取正文，模型不负责重写正文。
已有文档首次纳入数据库时也默认关闭，不会自动产生模型调用费用。

关闭后再次开启会复用有效摘要；编辑原文会使旧索引失效。管理页保存后自动关闭，手动开启才重新处理。
处理失败可点击重试，已完成的批次可复用。关闭会停止后续批次，正在进行的模型
请求可能仍会完成，但不能发布结果。macOS/Linux 上服务意外退出后，刷新会识别已退出的处理进程并显示可重试；
Windows 也检查进程是否退出；无法确认时保留任务并使用租约过期检测。最多同时处理两篇；超出时页面提示稍后重试。

首次创建知识库后启动新的 Corki 会话，运行时会注册 `knowledge_search` 和
`knowledge_read`。前者浏览文档/段落简介，或用 BM25 排序召回段落；后者按需
读取原文并返回引用位置。开关、删除及源文件变化在工具调用时重新检查。
BM25 复用工具发现评分器，中文使用字符二元组；索引在检索时从摘要构建，
不是磁盘全文索引，也不需要 embedding。正文不会整库放入模型上下文。
禁用只能阻止后续检索，已经进入对话的内容不会从历史中移除。
管理页面的搜索框筛选列表信息；Agent 检索通过上述知识工具执行。
不将“已保存”显示为“已索引”。MCP 列表目前只管理用户配置，不包含 mcporter、
插件注入、运行时临时工具；已配置不代表连通。网关指示仅检测端口，不验证账号。

配置更改供新的 Corki 会话使用，不强制刷新正在运行的会话。Skills 清单读取
Corki 用户与内置目录、通用 Agents 目录，以及选定项目中的对应 skills 目录，不表示已经
覆盖插件缓存或所有上级项目目录。会话状态来自数据库，不表示进程实时存活。

## 写入与数据保护

- 所有测试使用临时目录；真实配置不作为测试数据修改。
- 修改前比对 SHA-256 版本，避免覆盖已变化的文件；原文件保存在同目录
  `.manager-backups/`。这能发现写入前的外部更新，不是跨进程事务锁。
- 原子替换文件，macOS 使用文件权限 0600，Windows 使用当前用户私有 DACL；保留未修改配置区块及其注释。修改的区块会
  重新序列化，区块内部原注释可从备份恢复。
- 知识库删除会直接移除正文、索引与版本历史，不移入回收目录，删除后无法恢复。
- 仅接收本机合法 Host、同源 Origin 和管理页自定义请求头的写请求。
- 普通列表不回显供应商密钥；完整配置编辑器及历史预览会展示原始配置（含密钥），只在本机使用。文本日志输出隐藏已知配置凭据和常见 token 格式。
  日志源仍应避免主动记录秘密，模式匹配无法识别所有任意敏感内容。
- 本机其他程序具有访问服务的能力，不能当作多用户或公网管理服务部署。

## 配置版本

配置页直接编辑用户目录下的 `settings.json`，沿用 Corki 的 JSONC 规则（支持注释和
尾逗号，拒绝重复键及非有限数字）。输入停止后自动校验，保存前再次校验；错误不写入
文件。模型详情仅展示常用参数，保存时保留其他模型元数据。

历史版本存放于 `~/.corki/manager/config-versions/`，macOS 目录权限 0700、文件 0600；
Windows 的私密文件使用当前用户私有 DACL。
版本文件包含完整凭据，不写入 IndexedDB/localStorage。配置表单写入同样记录版本；读取
版本列表时会记录外部修改后的当前配置。未被观察到的外部中间修改无法追溯。
保存后立即替换配置文件，回滚会追加一份新版本；旧版本保留，当前相同内容的
重复保存不创建冗余版本。未保存的编辑在页面内切换时保留，离开浏览器页面有提示。

新会话通过 Corki 正常配置加载流程读取；已有会话不会热更新。环境变量、项目配置
或会话选择仍遵循 Corki 原有优先级，并可能覆盖对应用户配置项。

## Skills 目录与导入

- 内置：`~/.corki/skills/.system/`，只读，由 Corki 更新。
- Corki 专属：`~/.corki/skills/`，可编辑；现有项目技能也保留展示并标注「项目」，项目文件只读。
- 公共：`~/.agents/skills/`，可编辑，导入默认写入此处。公共文件修改会影响共用它的 Agent；启停只修改 Corki 本地配置。

导入支持一个完整技能文件夹、ZIP 或单个 `SKILL.md`，先预览校验，再整包写入。
技能包不限制文件数量和总大小；SKILL.md 入口仍遵循运行时 128 KB 读取上限。使用运行时同一 frontmatter 解析器；
导入使用 SKILL.md 的 name 作为安装目录名，不允许自定义名称。包内如有技能目录，其目录名必须与 name 一致；根目录直接包含 SKILL.md 的 ZIP 按 name 安装，ZIP 文件名不参与命名。已有技能不迁移；管理页不提供改名，编辑 SKILL.md 时须保留原 name。同目录或同名技能不覆盖。拒绝路径跳转、重复路径和 ZIP 符号链接；跳过系统元数据，保留普通隐藏资源文件。
ZIP 的执行位会保留，文件夹上传不携带文件权限。导入不会运行脚本、安装工具或授权账号。
执行位适用于 macOS/Linux；Windows 上不能依靠 ZIP 的 Unix 执行位或 `.py` 文件关联启动脚本，
应使用已安装的解释器和独立参数。

### 技能文件工作区

技能详情提供可展开的目录树和文件搜索，支持 Markdown（含 YAML 头部）、Python、
JavaScript / TypeScript、JSON、YAML、Shell、XML 和 CSS 高亮，以及行号、折叠、查找与撤销。
默认只读，用户/公共技能通过「编辑」「保存」修改单个文本文件；内置和项目技能由 API 强制只读。
切换文件保留草稿、光标和滚动位置，关闭有草稿提示，Cmd/Ctrl+S 保存当前文件。
并发修改会拒绝覆盖并保留草稿；保存保留脚本执行位，旧内容写入管理备份。

ZIP 导出保存后的整个技能目录，保留文件原始字节、目录和执行权限，不包含管理备份、
Git 目录、Python 缓存及符号链接。支持常见位图预览；文本/图片在线读取上限 256 KB，
更大的文件和其他二进制可导出后查看。目录清单上限 2000 项，导出总文件大小上限 32 MB。

管理页以 `#FF6A00` 为品牌橙，深橙用于文字和主要操作，浅橙用于选中与聚焦状态；
成功、警告、错误与 diff 增删保留各自的语义颜色。编辑器全部本地打包，无 CDN。


## 自定义工具

每个文件定义一个工具，保存在 `~/.corki/tools/custom/<name>.json`。
管理页面可直接维护这些文件；不会将其写入 `settings.json`。
“导入工具”支持上传或拖入单个 JSON 文件，也支持粘贴完整 JSON；导入前校验字段，按 JSON 的 `name` 保存，拒绝覆盖同名工具。
Corki 初始化运行时时读取文件，注册为 `custom__<name>`，模型看到名称、描述和参数定义。
启停、编辑或删除将在下次初始化运行时生效，已启动的运行时保留自己的配置快照。
同名文件不可覆盖新增；更新校验文件版本，删除直接移除工具 JSON 文件，不移入回收目录，删除后无法恢复。

HTTP 示例 `query_order.json`：

```json
{
  "name": "query_order",
  "description": "根据订单号查询订单信息",
  "transport": "http",
  "url": "http://127.0.0.1:18000/orders/query",
  "parameters": {
    "type": "object",
    "properties": {"order_id": {"type": "string", "description": "订单号"}},
    "required": ["order_id"]
  },
  "timeout_seconds": 30
}
```

HTTP 默认使用 POST，请求体直接为模型给出的参数对象，如 `{"order_id":"123"}`。
设置 `method: "GET"` 时，参数编码为 URL 查询参数，保留地址里已有的查询参数。
接口返回 JSON 或纯文本即可，无需 MCP 初始化或 `tools/list`。非 2xx 状态视为失败，不自动重试或跟随重定向。
可添加 `headers` 字符串对象；也支持在文件中使用 `env_headers`，其值是本机环境变量名称。

本地进程将 `transport` 改为 `process`，以 `command`、`args` 替代 `url`：

```json
{
  "name": "echo_text",
  "description": "回显输入文本",
  "transport": "process",
  "command": "python3",
  "args": ["/absolute/path/echo_tool.py"],
  "parameters": {
    "type": "object",
    "properties": {"text": {"type": "string"}},
    "required": ["text"]
  }
}
```

`echo_tool.py`：

```python
import json
import sys

arguments = json.load(sys.stdin)
print(json.dumps({"text": arguments["text"]}, ensure_ascii=False))
```

每次调用启动一个进程，参数对象写入 stdin 后关闭输入；stdout 为结果，stderr 为诊断，退出码非零表示失败。
示例中的 `python3` 和脚本路径需要换成当前系统的实际值；Windows 可使用 Python
可执行文件完整路径，JSON 路径中的反斜杠需写为 `\\`。管理页格式指引使用管理服务自身的
Python 解释器路径，避免假设 Windows 安装了 `python3` 命令。
命令和启动参数直接传递，不做 shell 插值。可选 `cwd`（默认为当前工作空间）、`env` 和 `timeout_seconds`。
参数定义沿用 Corki 工具执行器支持的 JSON Schema 子集，不会自动补齐 Schema 的 default 值。
`enabled` 默认为 true，设为 false 后下次启动不注册。配置文件限 256 KB，单次输出限 1 MB，超时范围 0.1–300 秒。
本地及 HTTP 工作进程均使用 Corki 的执行权限编译与审批检查；受限网络或文件访问可能被当前沙箱策略拒绝。


自定义工具可在添加/编辑窗口或卡片上点击“测试”。输入调用参数后，会通过与运行时相同的工具执行器校验参数并真实调用；不会保存或修改配置。
测试可选择 JSON 或非空文本返回格式；默认 JSON。执行异常、HTTP 非成功状态、非零退出码、超时、空输出或返回格式不符均标记失败，原始输出可以查看和复制。
测试成功只表示执行与所选格式校验通过，不代表业务语义正确。测试上限为 30 秒；关闭结果窗口不会撤销已经发出的业务请求，页面不会自动重试。

## 主页快捷工具

快速配置从 `templates/quick-setup.json` 生成完整的新配置，不与旧配置合并。单选厂商与模型、填写 API Key 后，所选组合自动设为默认，默认上下文窗口为 256K（262144 tokens）；模型按当前接口支持范围写入 `supported_reasoning_levels`，支持 `medium` 时优先使用，否则采用模型默认行为。当前接口没有可用推理等级时写入空列表，不向上游发送该参数。管理页与 CLI 按此目录显示可选等级。接口地址和协议由服务端模板固定：OpenAI 使用 Responses，其余使用官方 Chat Completions 兼容接口。写入前校验并保留旧版本，遇到并发修改拒绝覆盖。现有 Corki 会话不强制切换，新启动实例读取新配置。

模型管理首页的“快速添加”复用同一模板，可在单个供应商下多选模型并一次添加。已有供应商会保留连接设置、密钥和其他模型；任一所选模型已存在时整次添加会被拒绝。现有默认模型保持不变；在空配置中首次添加时，第一个所选模型会成为默认模型。写入仍会校验配置并创建历史版本。

模板覆盖 DeepSeek、Qwen、Kimi、OpenAI、Claude、Google Gemini、GLM、MiniMax、xAI、Mistral；按可用的最近三代组织，记录官方来源和核验日期。DeepSeek 当前仅有两代通用 API 模型；不以旧模型别名补足。MiniMax M2.7/M2.5 的新用户接入截止日为 2026-10-19，届时自动从快速配置隐藏；套餐专用预览模型未纳入。目录是版本化静态模板，需要随官方发布更新，并非实时模型发现。Qwen 使用北京地域、MiniMax 使用国内平台、Gemini 使用 AI Studio API；套餐或其他地域密钥应在模型管理中单独配置。

Claude 使用其官方 OpenAI SDK 兼容接口，支持基本聊天和工具调用，不承诺与原生 Messages 全功能等价。Chat 运行时保留同一接口、同一模型返回的推理内容及工具签名，以支持 Kimi/DeepSeek 推理回传与 Gemini 工具循环；切换接口或模型时不回传这些专有数据。

快速启动可输入工作目录、通过系统窗口选择目录，或留空使用 Corki home 下的 `main/default`。
macOS 的 CLI 模式优先使用 iTerm，否则使用 Terminal，首次使用可能需要系统自动化授权。
Windows 的 CLI 模式使用管理服务的 Python 在独立系统控制台运行 Corki，不要求安装
Windows Terminal、Git Bash 或 WSL。两种平台都使用当前管理服务的 Corki home。

### 定时任务

左侧「定时任务」可创建、编辑、启停、立即运行、停止执行及查看最近 50 次结果。
每次执行创建独立 Corki 会话，使用任务保存的供应商、模型和当前权限配置；支持正常工具、
Skills 和知识库检索，不带入交互会话历史。结果保存在本机，可在执行记录中复制。

- 每天、每小时、一次性时间和五字段 Cron；新任务默认使用浏览器所在电脑的本地时区，可配置工作目录。
  `30m` / `every 30m` 表示重复间隔，`in 30m` 表示一次性延迟。
  未指定目录时使用当前 Corki home 下的 `main/default`，首次执行时创建。
- Manager 进程启动调度器。关闭网页不影响调度；关闭 Manager 后不再触发新任务。
  也可独立运行 `python -m corki.cron --home ~/.corki`，无需打开管理页面。
  同一个 home 多个服务同时启动时只有一个拥有调度锁，其余自动等待接管。
- 任务和记录放在 `~/.corki/cron/cron.sqlite`（随 `CORKI_HOME` / `--home` 改变），
  使用 SQLite 事务一起提交调度推进和执行记录。运行会话放在现有 sessions 数据库。
  任务配置独立于 `settings.json`，不会改写用户模型配置。
- 同一任务不重叠，全局最多两个执行进程。错过多个周期只补一次，不追赶全部历史时刻；
  执行期间错过的周期跳过。暂停只停止后续调度，停止按钮取消当前执行。
  手动立即运行不改变原来的计划；一次性任务执行后自动关闭。
- 工作进程独立于 Manager，服务重启后仍可完成。进程意外退出且结果不明时，记录为
  「待确认」并暂停任务，不自动重跑；确认之前的操作后再手动恢复。不能保证外部操作
  exactly-once；停止执行也不会撤销已经完成的操作。
- 交互审批不会自动批准，需要用户输入的任务会结束并提示调整；网络重试有界，
  连续 600 秒无运行事件视为超时。结果正文最多保存 2,000,000 字符。
- 首次启动调度服务后，新建 Corki 会话会发现 `cron_manage` 工具，可在用户明确要求时
  管理同一组任务。已有会话需要重新启动才能加载新增工具。

实现参考 Hermes 的 `cron/jobs.py`、`scheduler_tick.py`、`executions.py`、
`scheduler_authority.py`：执行前持久化、独立执行身份、错过调度的合并、状态不明不重放、
按 IANA 墙钟计算 Cron。Corki 使用单个 SQLite 事务代替 jobs.json 与执行账本之间的
跨文件协调，使用系统文件锁判断工作进程存活，避免 PID 复用误判。
当前仅本地 Agent 任务与结果管理，未引入 Hermes 的聊天平台投递、外部网关和脚本专用任务。

「仅一次」支持 ISO 8601、`YYYY-MM-DD HH:mm[:ss]`、斜线/点号/中文年月日、
`YYYYMMDDHHmmss`、10 位 Unix 秒时间戳（可带小数）、13 位毫秒时间戳，
以及「今天/明天/后天 09:00」「30分钟后」「in 30m」。日期不含时间时取当天零点；
没有时区的日期按任务本地时区解释，时间戳和带偏移日期保持其绝对时刻。
仅一次模式中的 `30m` 表示一次性延迟；已有固定间隔任务仍按原规则重复执行。无效日期及过去时间拒绝保存。

「每小时」的时间输入显示 `xx:00`，分钟可修改为 00–59；例如 `xx:35` 对应 `35 * * * *`，在每小时第 35 分钟执行。

「运行记录」页签汇总所有任务当前保留的执行记录，按运行顺序倒序分页（每页 20 条）。支持按任务名称多选筛选，筛选在分页前完成。任务列表中的「执行记录」直接切换到此页并选中该名称。列表展示执行时的任务名称、运行时间和状态；详情展示起止时间、耗时、任务内容、结果及错误信息。

新建任务必须选择模型供应商和运行模型，初始选中当前全局默认值；切换供应商后选中其第一个模型。任务只保存供应商及模型标识，执行时读取最新连接配置。旧任务未指定模型时继续跟随默认模型；已指定但被删除的模型会报告失败，不会静默切换到其他模型。

### 数据库管理

开发者 → 数据库管理：SQLite 数据库目录、表数据搜索与分页、字段结构、JSON 高亮行编辑、记录新增和删除。仅发现 Corki home 根目录及 `sessions/`、`cron/`、`memory/` 下的 SQLite 文件；不扫描项目、上传文档或备份目录，不接受任意文件路径。修改使用事务、外键约束及记录版本校验；视图、虚拟表、SQLite 内部表和不能唯一定位的记录不开放写入。二进制使用 `$blob` Base64 标记，超出 JavaScript 精确范围的整数使用 `$integer` 字符串标记。


此页面直接修改底层记录，不调用业务层工作流，SQL 查询使用独立页面，支持选中执行或执行全部（每批最多 50 条语句），写操作需确认；整批成功后提交，任一语句失败整批回滚。每条最多返回 200 行，整批结果最多 4 MB，执行时限约 5 秒（锁等待最多 3 秒）。不支持外部数据库挂载、扩展加载、连接设置或手动事务控制。数据库更改是否立即反映到运行中 Agent，取决于对应业务重新读取数据的时机。

SQL 查询标签支持创建、双击改名及自动保存；每次执行生成独立结果标签，展示每条语句结果。查询和结果持久化到 `~/.corki/manager/sql-workspace/<查询ID>/`，与业务数据库分离。关闭结果标签直接删除其结果文件；关闭查询标签删除查询及全部结果，不进入回收站或备份。最多保留 100 个查询、每个查询 100 个结果，结果总空间约 64 MB，达到限制时需先关闭旧标签。浏览器 localStorage 仅保存待同步草稿及选中标签，服务端保存版本用于避免多页面相互覆盖。

每次执行有独立请求 ID，重复发送不会重复写入。若服务在数据库提交和结果落盘之间中断，结果标为“状态未确认”，不会自动重跑 SQL。

失败的定时任务详情显示“异常日志”。新执行会保存经过凭据脱敏的异常堆栈或 Agent 错误（最多 64 KB）；旧记录优先读取对应会话的错误，无法恢复时显示原有失败原因。日志随运行记录一同清理。

### 快速启动方式

主页的快速启动支持桌面应用（默认）和 CLI。两种方式都使用所选工作目录，
留空使用当前 Corki home 下的 `main/default`，并保留配置有效性检查。
桌面模式查找本仓库 `app/out/Corki-darwin-*/Corki.app`，再查找
`/Applications/Corki.app` 和 `~/Applications/Corki.app`；未安装时显示明确提示。
通过独立参数传递目录，不拼接 shell 命令。桌面应用已运行时由单实例入口接收目录，
打开新会话草稿，不停止已有会话。更新此功能后需重启管理服务及旧版桌面进程。

Windows 桌面模式优先使用 `CORKI_DESKTOP_EXECUTABLE` 指定的完整可执行文件路径；
未设置时查找匹配当前架构的 `app/out/Corki-win32-<架构>/Corki.exe`，再查找
`LOCALAPPDATA`、`PROGRAMFILES`、`PROGRAMFILES(X86)` 下的 `Programs/Corki` 或 `Corki`。
不从 PATH 查找同名 `corki.exe`，避免误启动 pip 安装的 CLI 入口。
这些说明描述已实现的查找规则；Windows 全流程验收仍需包含安装、实际启动和退出。

### 知识文档详情与版本

点击文档打开独立详情页，使用 Markdown 高亮编辑器。内置文档只读；用户文档点击编辑后保存。
用户文档在 `manager/knowledge-versions/<document_id>/` 保留最近 20 个版本，支持查看、对比当前及恢复。
保存或恢复后自动关闭文档，不触发模型请求。手动开启时显示加载弹窗，通过默认模型完成摘要校验后才开启；失败保持关闭并显示简短原因。摘要有效且正文未变更时复用现有摘要。

### Hooks 管理

开发者 → Hooks管理提供用户级 Hook 的新增、编辑、删除和启停，以及总开关。
支持运行时现有的 11 个事件、本地命令和 MCP 工具；MCP 参数使用 JSON 编辑器。
另支持提示词和 Skills 两种上下文处理器，仅适用于 SessionStart、SubagentStart、
UserPromptSubmit、PreToolUse 和 PostToolUse。它们向当前 Agent 提供上下文，不启动额外模型调用。
Skills 可从当前技能空间中选择，或上传文件夹、ZIP、SKILL.md。上传包单独保存至
`~/.corki/hooks/skills/<ID>/`，保留脚本和参考文件，不参与普通 Skills 目录发现。
取消上传或删除最后一个引用的 Hook 时清理私有包；不会删除普通 Skills 中的原文件。
Hook 引用与 Skills 页面的启停状态相互独立；只遵循 Hook 自身开关和 Hooks 总开关。
新配置写入 `~/.corki/settings.json` 的 `hooks`，也可以管理已有的
`~/.corki/hooks.json` 中的配置。启用表示信任当前处理器，使用运行时相同的
规范化指纹写入 `hooks.state`。删除或编辑导致索引变化时，迁移其余处理器的
原有信任状态，不自动信任其他未批准配置。修改使用版本检查，配置变更进入历史。
新会话读取更新后的配置；页面不会为了测试而执行命令。项目级、插件及宿主管理的
Hooks 不在此用户级编辑页的管理范围内。

## 主页全局配置

开关逐项保存至 `settings.json`，沿用配置版本历史和冲突检查。免审批开启时使用
`default_permissions: ":danger-full-access"` 与 `approval_policy: "never"`；关闭时恢复
`:workspace` 和 `on-request`。记忆使用 `memories.enabled`，自进化设置存储于
`features.self_evolution`。已有任务继续遵循其启动时载入的配置。

会话自动清理由 `sessions.auto_cleanup` 控制，默认关闭。开启后，管理页面打开时会
在 `manager/maintenance.db` 原子记录启动时间；距上次启动超过 24 小时才再执行。
清理在后台进行，以三个自然月为界，复用核心物理删除能力；重新检查最新活动时间，
跳过运行中或持有写入锁的会话。会同时清理对应桌面草稿和元数据，不删除工作目录、
用户项目文件或共享记忆。清理删除的会话不可恢复；SQLite 释放的空闲页可由后续数据复用。

## 套餐转发

「主页 → 工具箱 → 套餐转发」连接独立 `adaptor/openai` 网关。开启前检查本机 Codex
文件登录，自动创建或更新 `adaptor-openai`；模型管理分为自定义供应商与系统适配供应商；系统适配分组默认折叠，仅展示已开启的供应商。启停统一在套餐转发页面操作。先开启网关，再启用供应商；供应商开关仅修改对应配置，关闭全部供应商也不会停止网关。网关关闭时不能开启供应商；关闭网关会停用对应供应商，但保留其配置。
关闭保留模型配置；系统适配供应商的连接设置只读。供应商 `enabled` 默认为 true；关闭后不进入运行时模型目录，模型创建也会拒绝。

地址格式为 `http://127.0.0.1:端口/openai`。管理页仅显示端口；开启时默认使用 17001，
占用时由独立网关直接绑定系统分配的空闲端口。页面与供应商配置同步使用实际端口，重复开启不迁移正在运行的实例。
`adaptor-` 为管理页保留前缀，不能通过普通添加或重命名供应商创建。可修改其模型配置，
连接参数由套餐转发页面管理。网关保持独立依赖；管理服务通过独立解释器的 JSON 控制入口调用，
不导入或复制上游转发实现。登录 Token 不进入页面、供应商配置或控制命令参数。
