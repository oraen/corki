# 应用管理

入口：主页 → 服务开发 → 应用管理。应用定义不会写入 `settings.json`。

- **LLM 应用**：提示词直接交给现有模型适配器；不启动 Agent，不注册工具。
  可以关闭本会话上下文；历史仍然保留。上下文按模型容量保留最近完整轮次，
  超出部分只从模型请求中省略，不删除展示历史。
- **Agent 应用**：复用 Corki Runtime、工具、知识检索、Skills、审批及压缩。
  所选 Skills 是明确的优先入口，不是能力白名单。禁用的 Skills 不会自动开启。
  首版禁止后台自进化、长期记忆读写和全局 Hooks，不修改用户原设置。

供应商与模型使用当前 Corki 配置；“默认”遵循供应商及其默认模型的现有选择规则。
显式模型失效会报错，不默默切换。应用模型选择不会改变全局默认。
工作目录固定到每个会话；修改应用目录只影响新会话。

卡片显示从 100000 起递增的应用 ID，可直接复制；删除后不复用编号。已有应用会在
启动时补齐编号，内部会话、版本和用量关联保持不变。卡片同时显示最后修改时间，
对话入口位于详情页。关闭应用只阻止新的轮次，不中断已接收的任务，也不删除历史；
开关独立保存，不额外生成提示词版本。

应用列表顶部提供独立的 aiohttp 应用网关，可在接入设置中选择端口、复制密钥及查看调用示例。
协议与启动说明见 [应用调用网关](application-gateway.md)。

## 编辑和版本

配置分为“基本信息”和“提示词”两个标签，切换保留表单草稿、编辑器及撤销记录。
提示词使用 CodeMirror Markdown 编辑器，编辑后显式保存为新版本；浏览器草稿按应用隔离。
创建前不生成历史记录，创建成功后产生首个版本。保存通过版本号检测并发冲突，内容
不变时不生成版本。服务端保留最近 20 个完整应用配置快照；提示词页仅列出提示词有
变化的快照，因此版本编号可能不连续。历史只读查看，与当前对比也仅比较提示词。

提示词回滚只恢复所选快照的提示词，保留当前名称、模型、工作目录、权限和 Skills。
内容确有变化时，回滚产生新版本；内容相同则不增加重复版本。在途轮次仍使用开始时
的配置，后续轮次使用新配置。历史元数据仅由配置界面请求，不增加运行状态查询的
历史解析开销。

## 数据与运行

所有路径跟随 `CORKI_HOME`，默认 `~/.corki`：

- `applications/applications.db`：定义、版本、会话归属、运行状态及 LLM 展示记录。
  长提示词只保存在版本中，当前定义通过版本号读取；卡片使用独立摘要字段，
  不解析长提示词。Agent 只额外保留未形成核心消息项的中断文字，以及尚未被核心
  接收的用户输入；这些内容不用于恢复模型上下文。
- `applications/runtime/sessions/`：现有核心存储管理的 Agent 展示历史、模型上下文、
  检查点及子 Agent 数据。应用模块不保存重复的 Agent 完整上下文。
- `sessions/corki.db` 的独立用量台账：两类应用的实际用量，来源为“应用”；以稳定
  step ID 去重。删除应用和会话不会删除用量。

任务由一个受操作系统文件锁保护的后台事件循环拥有，最多同时运行四个任务。
同一会话只允许一个活动轮次。浏览器离开不停止任务；重新打开读取权威快照。
活动轮次使用事件序号查询，未变化时不传输正文，也不重复加载整段历史。
稳定提交 ID 防重复；断线不自动重跑有副作用的工作。服务进程崩溃后，遗留运行
标为失败，可查看已保存内容。LLM 增量约每秒保留一次，异常退出可能丢失最后一秒。

当前执行所有者存在时，另一个管理服务不能接管执行或删除任务。
这是本机单所有者设计，不承诺多管理进程间的实时流式协同。

删除会话清理其模型上下文和历史；删除应用还清理定义与版本。派生子 Agent 按核心
来源关系清理。共享 Skills、工具、供应商以及工作目录中的文件不删除。

## 开发与验证

管理页与 Python 模块仍通过现有 manager 启动，新增静态资源由
`npm --prefix manager run build` 构建。Electron 打包脚本包含应用模块和静态资源。

```sh
.venv/bin/python -m pytest manager/tests/test_applications.py
.venv/bin/python manager/tests/application_fixture.py --info /tmp/corki-applications-qa.json
# 使用 fixture 输出的本机 URL，不使用真实管理服务：
CORKI_APPLICATION_TEST_URL=http://127.0.0.1:<port> node manager/tests/applications_e2e.mjs
CORKI_APPLICATION_TEST_URL=http://127.0.0.1:<port> node manager/tests/application_prompt_versions_e2e.mjs
```

`/api/applications` 复用管理服务的同源保护；不是公开推理 API。
API Key 只在服务端模型连接中使用，不进入应用定义、版本或页面。

## 核心接口调整

应用业务代码均在 `manager/applications/`，核心不导入应用模块。必要的通用调整：

1. `corki.models.factory`：提取原有模型工厂及能力解析，核心旧入口委托给它。
   让 LLM 宿主直接使用公共接口，避免依赖 Runtime 私有方法或复制供应商实现；
   原有传输、重试及能力规则不变。
2. `LangGraphRuntime.create(allow_self_evolution=...)`：默认保持原行为。
   嵌入宿主可明确禁止自进化，且用户配置重载不能突破上限，子 Agent 继承该上限。
   仅修改普通 settings 标志不足以保证这一点；改用其他 home 又会改变工作 Skills
   的发现范围，因此增加通用宿主参数。应用仍使用原 Skills 目录与作用域。
3. `record_external_usage`：将直接模型调用的实际用量写入原有独立台账，以 step ID
   幂等写入。没有改变现有表结构、删除策略或已有会话数据。

管理服务只增加模块初始化、受控 API 路由和退出清理；前端通过独立工作区接入。
编辑器脚本首次进入应用管理时才加载。用量分析新增“应用”分类；Electron 打包
复制应用模块。没有更改 CLI、机器人路由或原有 Agent 执行循环。

## 验证范围

在 macOS arm64、Python 3.12 下完成隔离测试。覆盖直接模型传输、真实 Runtime
工具循环、审批批准/拒绝、补充问题、停止与部分回答保留、失败恢复、请求去重、
模型失效、配置版本、历史分页、用量保留、子 Agent 归属及物理删除。
使用本机 HTTP 假模型完成实际传输测试，没有向真实供应商发送私人内容。

浏览器在 1536×1024 和 1280×800 检查列表、编辑、Diff 与对话；完整流程及延迟
请求测试覆盖版本选择、回滚、切页/刷新恢复、草稿、菜单、删除和跨应用响应隔离。
从打包目录启动管理服务并验证模块、资源和应用保存。

Windows 真实系统未验收。第一版没有附件入口或公开推理 API；LLM 的长历史采用
容量内的完整近期轮次，不承诺逐字保留无限模型上下文。Agent 的压缩遵循 Corki
现有实现。应用删除不回滚已经执行的外部操作。
