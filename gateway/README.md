# Corki 转发网关

将消息渠道接入完整 Corki Agent。管理入口：**主页 → 工具箱 → 转发网关**。
与 `adaptor/openai` 的模型套餐适配无关，不使用它的端口，也不要求安装 OpenClaw。

## 接入

需要已安装 Corki 的 Python 3.11+ 环境，连接器需要 Node.js 22+，下载依赖需要 npm。
五个渠道的连接器源码、清单和锁文件随应用提供，SDK 依赖按需安装。
点击「安装」后，在后台从公网 npm 安装锁定依赖到 `$CORKI_HOME/gateway/node/<渠道>`；
Telegram 无额外 SDK，仅准备运行目录。安装禁止 npm 生命周期脚本。
卡片柔和闪动并显示「安装中／卸载中」，尺寸不变，不阻塞其他渠道操作。
卸载会停止该类型的全部接入及任务，删除其依赖；保留账号配置、登录信息、授权和核心历史。
重新安装后，按需开启具体接入。依赖不提交 Git，也不随 Electron 安装包预装。
旧版用户目录中的共享依赖会按渠道迁移，保留原登录信息。

在「对话接入」点击「新增接入」，选择已安装渠道、填写名称和凭据。开启网关后，打开该接入的开关并完成登录：

| 渠道 | 接入方式 | 前提 |
|---|---|---|
| WhatsApp | Baileys 配对二维码 | 手机 WhatsApp → 已关联设备；同一账号不要同时由多个客户端监听 |
| Telegram | 官方 Bot API 长轮询 | 在 @BotFather 创建 Bot Token；同一 Bot 不能同时使用其他轮询服务或 Webhook |
| 飞书 / Lark | 官方 Node SDK 长连接 | 企业自建应用，启用机器人，私聊消息读取和消息发送权限；订阅 `im.message.receive_v1`，发布应用 |
| 钉钉 | 官方 Stream SDK 长连接 | 企业内部应用启用机器人，选择 Stream 模式并发布；填写 Client ID 与 Client Secret |
| 微信 | 腾讯 iLink 扫码及手机验证码 | 开启接入后点击「扫码登录」才获取二维码；手机确认登录，服务可用性和账号资格由微信决定 |

各渠道支持**私聊文本**及分段文本回复；钉钉另外支持接收图片和图文消息。暂不支持群聊、语音、普通文件及机器人发送图片。

接入的“会话设置 → 兜底文案”可配置收到不支持格式（如视频、语音、普通文件）时的
文本回复，默认“暂不支持该格式的信息”；留空后使用默认文案。此回复不调用模型，
平台重复投递同一条消息不会重复发送。会话校验启用时，无权限用户仍优先收到拒绝文案。
修改兜底文案立即用于后续消息，不重置会话、不重连渠道。
扫码凭据只属于 Corki，不读写 OpenClaw 的账号目录。微信参考腾讯 `openclaw-weixin 2.4.8` 的实际接口；并非直接加载该 OpenClaw 插件。

微信在没有登录凭据时保持「扫码登录」，不会在启用或重启时自动生成二维码。
点击后才获取二维码并检查扫码状态；二维码过期后可在登录弹窗中重新获取，无需关闭再开启接入。
已有有效登录信息时自动恢复连接；登录失效后等待用户重新点击扫码，不自动刷新二维码。

接入默认关闭「会话校验」，开启接入后直接处理消息；关闭接入会停止其当前任务并拒绝新消息。

开启「会话校验」后，在「会话设置」右侧显示「会话申请」。每个用户的首条消息会登记用户名称、渠道用户 ID、第一条信息和时间，状态为「审批中」；未接入期间的后续消息忽略，不调用 Agent。点击「接入」后，该用户下一条新消息正常执行，先前消息不会补发或重放。审批中的申请也可直接「拒绝」。点击「踢出」将其标为「已禁用」，停止该用户未完成的任务并拒绝新消息；已完成的外部操作无法撤销，其他用户不受影响。可再次接入。

勾选校验后可以编辑「拒绝文案」「授权通知」「拒绝通知」，每项最多 2000 字符，空白使用内置默认文案。审批中或已禁用用户的每条新提问均回复拒绝文案，平台重投同一消息不重复回复；接入、拒绝或踢出时发送相应通知，不调用模型，不写入 Agent 上下文，也不会重复处理原始问题。更改文案不会重连渠道或重置会话。

通知通过原渠道异步发送，不阻塞接收消息和管理页面操作。网关关闭时先保存待发送通知，下次渠道连接后发送；更新的审批决定会覆盖尚未发送的旧通知。每个用户的最新回复上下文及通知状态位于 `access_delivery` 表；待发送通知及各自回复上下文保存在 `access_notice_queue` 表，发送完成或失败后即移除队列条目，两表位于本机受限权限数据库，可能含渠道临时回复凭据，不通过管理页接口公开。钉钉、微信等渠道的回复凭据可能过期；发送失败不回滚审批结果，列表会显示「通知未送达」。对送达情况未知的发送不自动重放，以免重复通知。首次申请信息、审批状态和通知状态相互独立。

申请按接入账号与渠道发送者 ID 隔离，保存在网关数据库 `access_requests` 表。关掉校验即恢复所有人可对话，但保留已有申请与状态，重新开启时继续生效。重置会话不清除申请；删除接入或更换登录账号时清除。列表分页加载，首次信息可点击查看全文；仅打开申请标签时跟随现有刷新周期更新，不增加后台轮询线程。标准 HTTP 队列会跳过未接入用户的消息并继续处理后续消息。
通过启用接入发来消息的用户可以使用该工作目录下的 Corki Agent 及现有权限，默认目录为 `$CORKI_HOME/main/default`。
每个对话接入可单独选择供应商和模型，默认沿用 Corki 全局配置。指定选择保存在网关本地数据库的 `agent_provider` / `agent_model` 字段，不修改全局默认值。该接入下的用户会话均使用此选择；每条消息开始执行时读取，运行中的任务不受影响。已删除或禁用的指定供应商/模型会报错，需要重新选择；不会静默改用其他模型。每个新消息启动时加载配置，不通过后台计时器反复加载。
工具执行审批、MCP 请求和补充问题在网关页面展示；普通执行审批可批准一次或拒绝，复杂 MCP 表单/URL 请求首版仅支持拒绝。

关闭渠道会停止该渠道的任务，保留登录信息；关闭网关会断开全部渠道并停止任务，保留各渠道的启用偏好。
「清除登录信息」会关闭渠道、删除该渠道密钥/配对凭据，需要重新配置；核心历史不会删除。
网关独立于管理服务，关闭浏览器不会停止它；再次打开网关会恢复已启用渠道，但不会自动重放中断任务。

## 多账号与对话绑定

同一渠道可以创建多个接入，组件安装一次，各接入的登录目录、密钥、消息游标、去重记录和运行状态独立保存。
同一平台账号重复启用时会拒绝后一个接入，避免重复轮询或消息重复执行。

会话按接入账号与发送者 ID 隔离，同一用户串行，不同用户受网关总并发限制。回复始终返回原消息发送者，没有可配置的会话模式。
「管理」页面左侧分页列出用户会话，每 5 秒刷新，支持切换及加载更早消息；钉钉还支持主动发送消息。
「重置当前会话」只停止所选用户的任务并更换其上下文；「重置全部会话」停止此接入的任务并更换所有用户的上下文。聊天记录保留，修改工作目录也需确认重置。
升级时移除旧的模式字段，保留已有用户独立上下文。旧的多人混合上下文留在历史存储中，不复制到任何用户的新上下文。

会话授权的 `token用量` 汇总该接入用户历次模型调用的输入与输出 Token，不重复加上缓存和推理子项。
`user_usage_threads` 单独保留用户与历史会话的归属，重置当前或全部会话不清除归属。
升级时从现有路由、回执及用户会话回填；无法确定唯一用户的旧混合会话不冒认归属。
列表只查询当前页用户，使用核心库 `model_steps_thread_usage` 覆盖索引；用量数据库不可读时显示 `—`。
统计来源仍为核心库已保存的模型明细，未返回用量的失败请求不估算；物理删除核心会话明细会影响对应统计。

接入基本信息默认只读，点击编辑后可修改。仅修改会话校验、名称、供应商或模型不会停止正在执行的任务；修改连接凭据等运行参数会停止任务并重新连接。用户独立会话只隔离聊天上下文，工作目录仍由此接入共用。
删除接入会永久删除该账号的凭据、授权、配置及网关路由，不删除核心会话历史。
删除自定义连接器前需先删除其全部接入。
原单账号配置自动迁移，保留原账号 ID、凭据目录和会话映射；空渠道不会生成空账号。

## 架构

```
manager（同源页面）
    → JSON 控制入口 gateway/bin/control.py
    → 优先 127.0.0.1:17003（被占用时由系统分配）+ 每次启动随机认证令牌
    → 网关 Host → 独立连接器进程（JSON Lines v1）→ 平台
               → Agent 适配层 → Corki LangGraphRuntime
```

- `src/corki_gateway/control.py`：单实例锁、启动/关闭、认证本地控制 API。
- `connections.py`：接入账号、用户会话绑定、旧版本迁移。
- `store.py`：网关配置、渠道游标、路由映射和去重记录，SQLite 事务。
- `service.py`：接入校验、排队、独立渠道监督/退避重连、运行状态、资源释放。
- `connector.py`：子进程协议、分包读取、请求关联、大小限制、超时、进程组/Windows Job 清理。
- `agent.py`：唯一的 Agent 适配点，复用核心运行时和持久化，不复制工具、模型或压缩逻辑。
- `connectors/`：五个内置连接器及依赖锁文件，使用时按需安装 SDK。

参考 OpenClaw 的责任边界：`src/gateway/server-channels.ts`、`src/channels/plugins/types.plugin.ts`、
`src/channels/turn/run-channel-turn.ts`、各渠道的收发与生命周期代码。
飞书以 `onReady/onReconnected` 判断已连接，而不是以 `start()` 返回判断；WhatsApp 只接收新 `notify`，忽略历史同步和自身回声。

相同渠道/账号下，以**会话 + 发送者 + 工作目录**路由至固定 Corki thread；更换账号清理该渠道授权和路由。
同一会话串行，不同会话最多并发 4 个，总等待任务上限 100，单任务执行上限 30 分钟。
接收消息后先持久化去重，再运行 Agent；去重记录保留 30 天。
不承诺跨崩溃恰好执行一次：重启把未完成接收记录标记为中断，不自动重跑可能有副作用的工具。
投递结果不明时不自动重复发送，运行记录保留错误，完整结果仍在 Corki 会话库。
运行时会话写入锁、工具权限、Skills、知识库和上下文压缩均由原核心负责。

## 数据

默认 `CORKI_HOME=~/.corki`（未设置时）：

- `gateway/gateway.db`：独立配置/状态库，密钥不返回浏览器，编辑留空保留。
- `gateway/accounts/<id>/`：各渠道的扫码登录数据。
- `gateway/plugins/<id>/`：用户安装的连接器文件。
- `gateway/node/<渠道>/`：各渠道独立的固定版本 SDK。
- `gateway/endpoint.json`：短期本地控制认证令牌，仅本机访问，退出删除。
- `sessions/corki.db`：原 Corki 会话库，来源标记 `gateway`。

POSIX 下目录为 0700、配置库和端点凭据为 0600；Windows 使用当前用户目录访问权限。
协议 stdout 不输出日志；第三方 stderr 只排空，不记录可能含密钥的原始 SDK 日志。
管理页面显示固定错误类别和运行状态，详细 Agent 错误在现有会话日志中查看。

## 启动与测试

在仓库根目录（先安装 Corki 环境）：

```sh
python -m pip install -e .
python gateway/bin/control.py
```

控制入口从 stdin 读取一个 JSON，stdout 返回一个 JSON，例如 `{"action":"power","enabled":true}`，
或 `{"action":"power","enabled":false}`。可传 `--home` 使用隔离数据。
也可安装独立包：`python -m pip install ./gateway`，随后使用 `corki-gateway`。
不要另开多个监听同一平台账号的网关。

```sh
python -m pytest gateway/tests -q
node --test gateway/tests/connectors.mjs
```

测试包括真实独立网关进程、真实连接器子进程、真实 Corki Runtime、可控本地 SSE 假模型、工具调用、
两轮历史恢复、去重、接入控制、停止/重启、子进程清理、恶意 ZIP 以及四种渠道协议适配。
不需要真实平台凭据。真实五个平台账号收发需由账号所有者登录后分别验收；模拟协议测试不能代替平台验收。
Windows 代码使用现有 Corki 进程适配，但本次尚未在真实 Windows 环境验证。

桌面打包脚本仅包含网关源码/连接器/锁文件，不携带用户数据、凭据或 node_modules。

## 钉钉接入说明

钉钉使用官方 `dingtalk-stream@2.1.5`（固定稳定版本），依赖按需安装。
参考官方 SDK 示例：https://github.com/open-dingtalk/dingtalk-stream-sdk-nodejs
只订阅机器人消息，通过出站 WebSocket 收消息，无需公网端口。
本版只处理私聊文本；群聊及非文本消息不触发 Agent。
消息被网关持久化接收后即 ACK，避免等待 Agent 完成造成重复推送。
回复使用该消息的 sessionWebhook，限制到钉钉官方 HTTPS 地址；凭据不写入运行记录。
回复窗口过期、投递超时或失败不会自动重复发送，结果仍保存在 Corki 会话中。
连接失败由网关监督器退避重连，不与 SDK 内置重连叠加。
无需改变 Agent 核心；多账号、工具审批、会话和停用继续使用网关已有流程。

网关优先直接绑定本机 17003，只有端口占用时才绑定端口 0，让系统分配空闲端口。实际端口继续写入 gateway/endpoint.json，管理端始终读取该文件，不假设固定端口。

## 标准 HTTP 连接器

无需安装依赖或上传 ZIP，填写两个 POST 接口即可接入。支持参数模板、SQLite 顺序队列、回执校验及回复重试。详见 [HTTP_PROTOCOL.md](HTTP_PROTOCOL.md)。

管理详情页按「会话记录 / 会话设置」切换。记录只展示用户消息和已完成轮次的最终回答；中间说明和未完成的流式草稿不展示，原始核心历史不删除。轮次元数据缺失的旧导入记录仅按明确的 commentary 标记过滤。

路由诊断标识保存在 `~/.corki/gateway/gateway.db`（自定义数据目录时跟随 `CORKI_HOME`）的 `routes` 表：`sender_id`、`sender_name`、`external_conversation_id`、`workdir`、`binding_id`、`last_seen`。其中 `external_conversation_id` 是渠道原始会话 ID，`binding_id` 是 Corki 自己的会话绑定。现有哈希键及会话不变；旧记录新增字段为空，后续新消息到达时补齐。不保存完整原始回调或回复凭据。删除接入时随原路由一并清理。

### 钉钉 AI 卡片

在对话接入的“会话设置”中编辑并勾选“启用 AI 卡片”，填写已发布的 AI 卡片模板 ID
（以 `.schema` 结尾）和模板的正文变量名（默认 `content`）。应用需开通
`Card.Instance.Write` 与 `Card.Streaming.Write`。默认关闭，普通文本接入不受影响。
卡片配置属于展示选项，修改不会重置会话、路由或用户授权；下一条任务生效。

每条任务独立创建卡片，先显示处理状态。只对明确标注 `final_answer` 的模型正文发送
节流后的流式更新；未标注的模型在任务完成时整体更新答案，不暴露内部推理和工具输出。
完成、失败、超时和停止均尝试结束卡片状态。卡片不可用时保留普通文本投递；长回复也
使用原有分段文本通道。管理授权通知仍发送普通文本，不占用任务回答卡片。

连接器在账号状态目录的 `cards/` 保存卡片 ID、投递状态及最终文本哈希，不额外保存
完整问题或回答；重复的最终卡片投递可以复用同一张卡片。普通文本回退仍遵循既有的
投递确认规则，不承诺网络异常下绝对不重复。实际模板字段、应用权限和客户端展示需用
用户自己的钉钉应用联调，隔离测试不会发送真实机器人消息。

### 钉钉授权通知重发

点击“接入／踢出”产生的通知优先通过当前会话回复；本地回复凭据过期，或钉钉明确
返回会话凭据失效时，自动尝试主动消息接口。网络超时、权限等其他错误不触发切换，
避免在送达结果不明时重复发送；已确认发送的分段也不会重新发送。

“会话授权 → 通知未送达 → 重发”使用钉钉的主动单聊消息接口，不使用临时
`sessionWebhook`。需开通“企业内机器人发送消息权限”，并已从用户的机器人消息
中取得 `senderStaffId`（企业 userId）。旧记录未保存此标识时，需用户再次发送消息
以补齐；不会将加密 `senderId` 冒充企业 userId。普通回复仍使用原会话回复方式。

失败详情保留“回复凭据过期”、HTTP 状态码、钉钉错误码、原因和请求 ID（如接口返回），
不记录令牌和临时回复地址中的凭据。重发只发送通知，不改变授权、不执行 Agent。
只有接口返回受理回执且该接收者未被拒绝或限流才记为已发送，不表示对方已经阅读。

### 钉钉会话记录与人工发送

钉钉“会话记录”按联系人查看收发内容，可折叠左侧联系人列表。底部输入区使用主动
单聊接口，以机器人身份发送人工消息。人工消息不会调用 Agent，也不加入模型上下文。
发送中、已发送及发送失败的结果会保留；失败消息可以点击查看原因。

网关在自身 `gateway.db` 的 `dingtalk_contacts`、`dingtalk_messages` 表保存联系人与
传输记录，含用户输入、Agent 最终回复、人工消息和权限/执行通知，不保存中间推理。
历史分页读取，界面沿用现有五秒刷新。请求 ID 防止同一人工发送因重复提交而重复执行；
崩溃后未确认的发送标记失败，不自动重发。

启用此版本前的 Agent 历史继续从原会话库按需读取；可恢复的最近一次权限通知及未授权
输入会补入记录。此前未保存的通知无法补齐。删除接入时一并删除其联系人与发送记录。

### 回答指引

每个接入可在“会话设置 → 回答指引”填写多行文本（最多 8192 字符）。默认不填写；
空白保存后不添加指引。可约定回答受众、表达方式，也可以要求按需阅读已有 Skills；
此字段不会自动安装或额外绑定技能。

`reply_guidance` 保存在此接入的配置中，保存不会重连渠道、重置会话或修改全局配置。
每次任务实际开始运行时捕获一份配置，运行中的任务保持原指引，后续任务使用新配置。
无后台轮询。程序产生的授权、兜底及错误通知仍使用各自配置，不调用模型改写。

指引使用运行时通用的 `request_context`：每次模型请求携带一份独立开发者消息，
Chat Completions 转为 `system`，Responses 使用 `developer`。原有 Agent 基础指令保留。
指引不追加进聊天历史或压缩摘要，压缩后、工具继续调用、重试及恢复后的新任务仍从
当前运行时前缀附带。Token 估算和接口字节检查都包含该前缀；内部摘要仍遵从专门的
摘要要求。它影响模型表达，不能代替工具权限控制，也不能保证模型每次都遵从要求。

### 钉钉图片输入

支持 `picture` 纯图片及 `richText` 图文消息，保留文字与图片顺序。一条消息最多 8 张，
每张最多 16 MB，支持 PNG、JPEG、WebP、GIF。先校验用户对话权限，再通过官方
`messageFiles/download` 获取图片；应用需有“企业内机器人发送消息权限”。使用接入
配置的模型（未单独配置时沿用默认模型），复用 Corki 既有图片处理和多模态输入能力。
未声明支持图片的模型、无效图片及下载失败会明确反馈，不会悄悄当作纯文本执行。
官方接口返回的 HTTP OSS 链接会升级为同地址 HTTPS 下载，不回退到明文传输。
先校验和下载图片，再创建任务 AI 卡片；图片任务失败时同时保证有可见的文字提示。

图片和缩略图存放于 `gateway/accounts/<账号状态目录>/images/`，元数据在
`dingtalk_assets` 表，消息引用位于 `dingtalk_messages.images`。通信和会话列表不传
图片 Base64 或临时下载链接；管理页显示缩略图、原图预览及失败原因。删除接入或清除
登录信息会清理该接入图片。文字与图片分开发送时是两个独立消息，沿用同一用户会话
顺序执行；不会用固定等待窗口延迟普通文本。

### 授权列表中的回复状态

会话授权保留审批中、已接入、已禁用三种持久状态。已接入用户正在处理的
Agent 回复显示为「回复中」，沿用管理页的 5 秒刷新；排队消息和授权通知
不计入该状态，网关离线时不沿用旧的运行标记。搜索支持昵称和页面显示的
用户 ID（钉钉为 `senderStaffId`）。

「终止」经确认后只取消打开确认框时的当前回复，不撤销授权、不取消后续
排队消息，也不影响其他用户。已完成的工具操作或已投递的消息无法撤回。
管理员通过停止图标确认终止后，用户收到「回答已被管理员终止」：优先更新原 AI
卡片，卡片不可用时发送文字；钉钉回复凭据过期时回退到主动消息。通知与发送
结果保存在钉钉会话记录中，重复点击不会重复通知。
管理请求 `applications` 附带 `reply_activity`，按 sender 索引当前
`message_ids` 和 `stopping`；`stop-reply` 必须携带接入 `id`、`sender` 及
捕获的 `message_ids`。已经结束的标识不会匹配下一次回复。

### 钉钉消息撤回

会话记录中，自方消息上方的「撤回」在悬停或键盘聚焦时显示。只有已发送且
保存了完整平台回执的消息可操作；缺少回执的旧消息按钮不可用，不猜测消息标识。
机器人主动发送保存 `processQueryKey`；AI 卡片保存投递回执中的 IM_ROBOT
`carrierId`，与用于更新卡片的 `outTrackId` 分开。会话 Webhook 未返回回执时
不能撤回，不为获取凭据而重复发送消息或更改已有通知的发送优先级。

管理请求 `recall-message` 携带接入 `id`、联系人 `session` 与本地消息
`message_id`。网关验证三者归属，只使用服务端保存的凭据调用钉钉单聊机器人
撤回接口。消息拆分发送时核对全部回执，部分成功保留剩余回执供手动重试；
网络异常、权限不足、过期或未明确确认成功都不会标记为已撤回。

凭据保存在 `dingtalk_messages.recall_receipt`，不返回浏览器。成功后界面
继续显示原文及附件，在下方以红色标记「已撤回」，Agent 上下文不变。重启不会自动重放
撤回。多个页面重复点击只触发一次正在进行的操作。真实平台可能限制撤回时间
和权限，以其响应为准。
