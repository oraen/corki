# 标准 HTTP 连接器协议 v1

在「渠道接入 → 标准连接器」填写名称、拉取问题接口、发送回复接口。接口由接入方实现；Corki 主动发起 HTTP 请求，不需要为本机配置公网回调。

没有参数，或创建时勾选「禁用参数解析」，会自动创建一条**关闭**的对话接入。开启网关和这条接入后开始工作。有参数的模板，在「新增接入」中选择连接器并填写参数。每条接入拥有独立队列、游标、会话和参数值。

## 通用要求

两个接口均接收 `POST`、`Content-Type: application/json`。返回 2xx 和 UTF-8 JSON 对象；重定向不会跟随。单次请求超时 15 秒，响应体最大 4 MiB。支持 HTTP（本机或可信网络）和 HTTPS，HTTPS 验证证书。不要把凭据放进日志。

## 1. 拉取问题

请求：

```json
{
  "protocol": 1,
  "connection_id": "account-example",
  "cursor": "",
  "limit": 20
}
```

响应：

```json
{
  "messages": [
    {"id": "question-1001", "sender": "user-01", "text": "帮我整理今天的工作计划"},
    {"id": "question-1002", "sender": "user-01", "text": "按优先级安排顺序"}
  ],
  "next_cursor": "cursor-1002"
}
```

- `messages` 必须是数组，每批最多 20 条，按返回顺序处理；空结果是 `{"messages":[]}`。
- `id` 必填：接入内唯一、稳定、非空字符串，最长 300 字符。重试拉取时保持相同 ID；不得重用 ID 表示不同问题。
- `text` 必填：非空文本，最长 100,000 字符。
- `sender` 可选：非空文本，最长 300 字符，默认 `remote`。同一接入所有发送者共用一份会话。
- `next_cursor` 可选：最长 65,536 字符的字符串，不解释其内容。整批通过校验且在 SQLite 中入库后，与消息在同一事务中保存。下一次拉取携带该游标。
- 任意一条格式无效则整批不接收、游标不前进。重复 ID 忽略，不覆盖已有问题。
- 拉取必须是可重试的非破坏性读取，不要在返回响应前就永久消费消息；崩溃或网络中断可能导致整批重新拉取。

只有本地队列清空后才继续拉取。空结果等待 1 秒；连续 10 次空结果后等待 5 秒；收到新消息恢复 1 秒策略。仅返回已去重的消息也视为没有新消息，避免忙轮询。拉取网络/协议错误间隔 5 秒重试。

## 2. 发送回复与回执

请求：

```json
{
  "protocol": 1,
  "type": "reply",
  "connection_id": "account-example",
  "message_id": "question-1001",
  "reply_id": "reply-unique-id",
  "text": "今天的工作计划如下…"
}
```

成功回执：

```json
{
  "received": true,
  "message_id": "question-1001",
  "reply_id": "reply-unique-id"
}
```

必须同时满足 HTTP 2xx、`received` 为布尔值 `true`、两个 ID 与请求完全一致，才认为回复被接收。空响应、仅 HTTP 200、字符串 `"true"`、ID 不匹配均不算成功。

**接收端必须持久化并按 `reply_id` 去重。** 重复请求只投递一次，但仍返回同样的成功回执。只有已经可靠保存/接收回复后才能确认；这不代表最终用户已阅读。Corki 不承诺跨进程崩溃的无条件恰好一次交付。

Corki 先把回复正文和 `reply_id` 入库，再发送 HTTP。默认首次失败后重试 3 次（总计最多 4 次），可配置为 0–20；等待依次为 1、2、4、5、5…秒。所有重试使用相同正文、消息 ID 和回复 ID，**不重复调用 Agent**。

收到匹配回执后标记已回复；次数耗尽则标记 `delivery_failed`（发送失败），保留回答和回执标识，继续处理下一条，不暂停接入。管理页的对应回答显示「回复失败」标签。不会因发送失败重新执行 Agent，也不会在重启后重新发送已经失败的记录。

`type:"notice"` 是工具审批/补充信息等中途通知，也使用以上回执。它不结束当前问题，不能被当成最终回复；最终回复仍为 `type:"reply"`。通知失败不改变最终回复队列状态。

## 3. 参数模板

地址的路径或查询参数可以写 `#{变量名}`，例如：

```text
https://example.com/questions?account=#{account}&key=#{access_key}
https://example.com/replies?account=#{account}&key=#{access_key}
```

变量名使用英文字母或下划线开头，后接字母、数字、下划线，最长 64 字符；最多 24 个不同变量。新增接入时填写参数，参数值保存于本机，普通状态查询不返回明文。替换时对整个值进行 URL 编码，不二次解释变量，不执行表达式。

不允许通过参数替换协议、主机或端口。域名不同时创建独立连接器。

「禁用参数解析」可在创建连接器时或有参数的接入设置中勾选。勾选后 `#{...}` 按普通字符发送，其中 `#`、`{`、`}` 会进行 URL 编码，避免被当作 URL 片段或变量。

## 4. 恢复与数据

- SQLite 队列位于 `$CORKI_HOME/gateway/gateway.db` 的 `http_inbox` 表；Agent 历史仍保存在 Corki 原有会话库。
- 网关重启后，尚未执行的消息继续排队；已有回复继续投递，已消耗的重试次数保留。已耗尽的回复作为发送失败记录保留，不阻塞后续消息。
- 如果 Agent 执行中途退出且没有持久化回复，无法确定已执行的副作用，**不会自动重跑任务**，需检查会话后显式跳过。
- 关闭接入停止拉取、发送和该接入运行任务；不会误停其他接入。队列保留。重新开启后继续安全恢复。
- 重置会话或修改工作目录会停止当前执行并跳过未完成队列；旧 Agent 历史保留。删除接入会删除其队列。
- 已回复/跳过的消息立即清理队列正文，仅保留去重 ID 等小型记录 30 天；发送失败的回答和状态保留，直到删除其接入。重置不会让这些旧消息自动执行。
- Agent 明确失败时，发送一条失败结果，获得回执后再处理下一条。执行审批仍使用 Corki 已有权限配置，不由标准连接器跳过。
