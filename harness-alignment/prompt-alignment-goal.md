# Harness 模型提示词对齐目标

本轮用户完整 /goal 为约束。参考 `<codex-source>`，实施仓库
`/path/to/corki`。目标是实际请求语义、角色、顺序和生命周期对齐，
不是单纯比较Markdown或替换产品名。

## 独立清单

- [x] 1 基础Agent指令、选择/覆盖/持久化、沟通及自主执行边界。
- [x] 2 工具描述/schema、通用渐进发现、成功失败取消重试与降级反馈。
- [x] 3 上下文初始化、动态更新、历史回放、压缩及继续执行。
- [x] 4 Memory检索/引用/生成/整理/更新/遗忘及记忆技能入口。
- [x] 5 Skills发现/触发/完整读取/资源/失败及来源绑定。
- [x] 6 AGENTS.md、项目环境、工作目录、权限沙箱审批配置。
- [x] 7 主循环执行/中断/恢复/排队/补充/收尾各状态。
- [x] 8 双方已有规划/协作/子代理相关提示；不为模板新增能力。

每项先读Codex模板/调用链/测试，记录启用分支；再审计Corki和最终请求，修复后
通过本地假模型/请求捕获及相关回归验收才勾选。不根据文件名或旧结论宣布一致。
将问题区分为模板语义、注入生命周期、实际能力差异；前两类修复，第三类仅做真实
能力适配，明显扩围先询问。互斥模型模板不混用，保留用户自定义指令优先级。

## 保护与排除

不复制官方登录/账户/额度/订阅/云任务，不恢复原生tool search/远程压缩namespace，
不扩展CLI或重启全面harness重构。普通供应商兼容协议不意味着启用官方功能。
不改teach.md及真实用户记忆/技能/配置，不提交推送；不读取密钥/剪贴板或使用付费模型。
保留已有架构适配（例如SQLite会话，不能声称JSONL）。已有memory skill路径修复保留。

## 验收与交付

核对最终请求的角色/顺序/触发/关闭/重复/裁剪/更新/恢复/压缩；检查低信任内容不会
被误提升、敏感配置不入提示或日志。测试按资源并行最多96workers，有冲突隔离。
全部八项有证据后才完成，最终交付具体修复、必要差异、测试结果、限制及记录路径。

## 起始状态

启动时 git status --short 为空。按当前提交作为用户基线，不修改Codex参考仓库。
审计记录见 `prompt-alignment-progress.md`。
