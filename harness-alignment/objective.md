  二、逐项审计并修复以下范围

  A. 主循环与 Runtime
  - Thread、Turn、Model Step 的边界及状态生命周期。
  - prepare → model → evaluate → tools → prepare 的真实循环。
  - 模型同时返回正文、reasoning、工具调用时如何处理。
  - 继续执行、完成、失败、取消、预算耗尽的判断。
  - 多工具调度、并行/独占、结果排序、执行期间的新输入。
  - 流式事件、backpressure、资源所有权及关闭顺序。
  - checkpoint、业务历史、模型结果与工具副作用之间的恢复关系。
  - 中断恢复是否重复用户输入、模型采样或工具执行。

  B. Tool Use：发现、召回、选择与执行
  - 内置工具、MCP、动态工具和扩展工具怎样注册。
  - Direct、Deferred、ModelOnly、CodeModeOnly、Hidden 等曝光策略。
  - tool_search 的启用条件、搜索元数据、索引、排序、Top-K、缓存与失效。
  - 模型如何发起搜索，检索结果如何成为后续可调用工具。
  - 仅普通 function-calling 的 tool_search、定义加载与工具调用链路；移除原生 tool_search_output。
  - 已发现工具的生命周期、上下文占用与恢复语义。
  - 模型选择工具和程序筛选候选之间的职责边界。
  - 内部分组到平铺函数名的稳定映射、schema 校验、调用身份和结果规范化；不使用原生 namespace。
  - 未曝光工具、未知工具、畸形参数、工具失效、超时和结果超限的处理。
  - Code Mode 与工具发现相关的路径及其适用条件。

  不能再把“全量直接曝光后由模型选择”描述为已经对齐 Codex 的按需检索。

  C. Context：构建、管理、压缩与召回
  - instructions、用户输入、项目规则、环境、工具定义和扩展信息的来源、角色及
  顺序。
  - 每 Step 更新、稳定 key、增量快照、删除/tombstone 与历史视图。
  - 完整请求的 token 估算、输出预留、工具 schema 和附件成本。
  - 自动/手动压缩的触发、时机、输入选择、摘要生成与失败处理。
  - 当前用户输入、关键约束、reasoning 和 tool call/result 的保留规则。
  - 压缩结果怎样替代模型可见历史，以及原始记录如何保存。
  - 连续历史召回、历史检索、长期记忆召回的区别及实际实现。
  - 恢复、取消或工具执行途中发生压缩时的一致性。
  - 普通模型请求的摘要生成与本地历史管理，不使用 provider 专用压缩端点或专有触发协议。
  - 无论 provider 名称、模型或地址如何配置，以上兼容路径和压缩所有权保持一致。

  D. Memory：短期、工作与长期记忆

  E. 错误处理与降级

  - 覆盖模型 HTTP 错误、流截断、缺失终态、部分输出后的失败与重试限制。
