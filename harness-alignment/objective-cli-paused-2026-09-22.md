四、CLI 交互活跃清单

F1 启动、布局与终端适配
- 冷启动/恢复会话、工作目录和模型信息、必要警告、空状态、输入区、状态栏与提示。
- 层级、间距、配色、高亮、加载与错误提示清晰一致；适度参考 Codex 风格，
  高频页面的整体信息层级、状态行和输入区位置尽可能接近 Codex；
  不以图标、动画或像素级复刻为目标。
- 常见终端宽度、窗口 resize、长文本、Unicode/中文输入输出可用；
  不遮挡关键操作、不明显重叠或残留；终端能力不足时可理解、可操作。

F2 输入编辑、提交与快捷键
- 普通/多行输入、换行与提交、粘贴、长输入、光标、最近输入导航和草稿保留；
  已提供的补全若影响基本输入则修 bug，不扩建补全系统。
- 不新增、不对齐、不逐项测试 Codex 的斜杠命令、技能/路径发现、命令菜单或
  快捷键体系。仅保证现有入口不破坏普通输入和基本退出；命令自身的功能扩展不在范围内。
- 运行期间新输入的排队/追加/steer、编辑与取消边界；不丢输入、不重复提交、
  不误消费下一 Turn 输入，焦点切换后草稿仍可恢复。
- 已提供的附件入口若影响基本提交，核对其真实状态；不新增附件功能。

F3 流式输出与工具呈现
- 正文、代码块、常见 Markdown、工具启动/执行/结果、错误与重试；已有
  reasoning/计划展示以不干扰正文和输入为准，不扩建专门交互。
- 流式增长、完整块提交、工具交错、长结果可读且不刷坏屏幕、滚动回看。
  不要求实现 Codex 式折叠/展开控件或完整 Markdown 呈现能力。
- 输出顺序稳定、无重复/跳字/闪烁/残影，结束后尾部不丢，失败的半截输出不伪装成功。
- 准确区分“思考/执行/等待用户/重连/完成/取消/失败”，避免无意义反复提示和假进度。
- 提交后到 Turn 终态之间有持续可见的工作状态；默认状态参考 Codex 的
  `Working` 行，显示本次执行的递增耗时与真实可用的中断提示。计时使用单调
  时钟，同一 Turn 内模型 Step/工具切换不重置；终态、取消、失败或退出后
  立即收束，不留下旧计时、spinner 或假“Working”。
- 状态行应在输入区附近保持稳定位置；等待工具、审批、重连、流式正文与
  无新输出期间都能正确更新，不靠新增对话消息刷屏。狭窄终端、resize、
  中文/宽字符及低动效/无动画环境下，状态、耗时和输入提示不互相遮挡。
- 对照 Codex `tui/src/status_indicator_widget.rs`、其 timer、bottom_pane
  与 chatwidget 的实际调用链，确认何时创建、刷新、隐藏状态；文案可以
  保持 Corki 身份，但不能省略用户需要的执行反馈。

F4 确认、审批与用户问答
- 实际操作、必要风险、权限请求和选项明确；选择、默认高亮、显式提交、拒绝、
  Esc/Ctrl+C 的行为有清晰边界。默认高亮绝不自动授权。
- 并发确认、后到弹窗、流输出/输入与弹窗竞争、焦点返回、取消/退出时提示撤销。
- 确认文本与用户答案不得串入普通命令/输入历史；过期回答不授予新请求权限。
- 涉及 shell/patch/MCP/Code Mode 的确认使用真实授权链，不以 UI 演示替代安全验收。

F5 中断、退出、恢复与历史
- 启动中/采样中/工具中/等待确认时取消，连续取消、EOF、正常退出、
  连接错误和恢复后的状态；不挂死、不重复 Turn 终态、不误报清理失败。
- 返回可输入状态、残留 spinner/弹窗消失、光标/终端模式恢复、子进程与资源释放。
- Running 状态和耗时在 Esc/Ctrl+C、关闭、故障及冷恢复中的起止点要准确；
  恢复后不能把旧 Turn 的计时当作新 Turn，也不能把失败后的静止屏幕伪装成仍在工作。
- 最近对话回看、已有会话恢复和返回输入；不误触发模型采样、重放副作用
  或丢弃草稿。历史分页、长会话专项仅在影响日常回看时修复，不作为新功能任务。

F6 基本配置与现有入口
- 只检查启动和普通对话实际依赖的模型/配置、帮助与必要状态提示；
  不新增 /skills 等命令，不扩展斜杠菜单，也不以补齐 Codex 设置入口为目标。
- 这些基本状态的显示应与真实生效状态一致；失败要可理解、可恢复。
- 没有明确需求不扩张为桌面应用、云端平台或全套新核心子系统。

1. 首先确认 Corki 当前可启动、可输入、可完成一次普通对话、可取消和正常退出。
   读取当前测试/进程状态，不把上次等待被打断理解为进程失败或自动重跑理由。
2. 优先修复 P0/P1：启动/崩溃/卡死、输入丢失、重复提交、审批越权、取消/退出失效；
   随后优先落实用户明确指出的 Working/耗时及执行过程反馈差异。
3. 再按用户使用频率修复交互小 bug，并整理布局、样式和必要细节，
   每批同时验证相关交互和呈现，避免“只有截图好看”。
4. 旧核心构造/调用迁移的未完成验证单独留档；只有影响 CLI 基线或本批行为时
   才做必要收尾，不要求先清空全部核心待办后才能开始 CLI。
5. 每批回到修订后的 F1–F6 活跃表，优先处理真实常用路径，记录关闭项和下一优先项；
   范围外的细节不作为持续扩建理由。旧 A–E 清单暂停。
   不因旧审计列有斜杠命令或其他非基本功能差异而继续开发。
6. 不读取/输出用户密钥，不为了测试真实联网或消耗用户模型额度；优先离线 fixture。
   真供应商验收需独立明确记录，不能用脚本模型冒充真实模型质量证明。

六、验收策略

- 能稳定复现的 bug 先添加会失败的行为测试，再修复；保持原安全/取消/恢复断言。
- 单元/状态机测试检查输入、焦点、确认、事件顺序和状态转换；
  终端渲染/快照检查布局与长内容；真实 PTY 检查实际按键、粘贴、resize、取消和退出。
- 对重要场景同时核对文本/状态与最终屏幕/终端恢复，不只断言“进程退出码为0”。
- 以空闲、生成、工具执行、必要审批、失败恢复和退出为代表场景，验证常见终端宽度、
  中文/长文本与新输入。复杂边界仅在出现真实故障或影响基本流程时追加，避免无界组合。
- Working/耗时至少验证：提交后出现、无输出时持续计时、正文和工具交错时
  不重置、跨秒/分钟格式、等待审批/重连的真实状态、取消/完成/失败后消失；
  使用可控时钟的状态测试和真实 PTY/终端快照双重验证，不能只测格式函数。
- 最终至少完成真实 CLI 闭环：启动→输入/编辑→流式回复→工具结果→后续输入
  →取消→退出；审批和已有会话恢复分别用相关场景验证，不强求单一脚本覆盖全部。
- 修复涉及核心层时运行对应核心回归；不默认每个 UI 改动都跑整个 A–E 全量。
  静态检查和本阶段 CLI 回归须完成，已有失败与环境限制如实列出，不跳过来伪造全绿。
- 验证所有测试进程实际退出；保留命令、并行数、失败原因、日志和最终结果。

  测试并行执行规则（用户授权）：
  - 恢复目标后，后续测试批次默认遵循本节：优先并行独立测试，96 为总 worker 上限；
    每批记录可复现的执行命令和实际并发数，不将“允许 96”理解为必须开满。
  - 每次全量回归前记录当前 CPU 逻辑核数、可用内存、已有测试进程及拟采用的
    worker 数；依据当前机器资源选择初始并发，不沿用未经重新评估的历史并发数。
  - 全量回归先按依赖和资源互斥关系分组；无依赖的组尽可能并行，以缩短总耗时。
    本条仅调整测试执行策略，不要求立即启动全量回归，以本次 CLI 活跃范围为准，不恢复已暂停的独立核心对齐任务。
  - 无依赖、无共享可变资源的测试优先并行执行；最多使用 96 个独立测试 worker
    （进程，不是线程）。96 是并发上限，不是固定值；根据 CPU、可用内存、I/O
    及测试创建的子进程数量选择实际并发，避免资源争用导致更慢或不稳定。
    多个测试批次同时运行时，96 上限按所有批次的测试 worker 总数计算，
    不得每批各开 96；逐步提高并发，并根据耗时与资源占用调整。
    测试内部如有线程池、进程池或外部服务子进程，也须计入资源评估，避免嵌套并行
    放大负载；实际采用低于 96 的 worker 数时，记录资源或隔离依据即可。
  - 执行前检查隔离条件：共享数据库、固定端口、文件路径或其它互斥资源的测试，
    应先隔离资源，或按互斥关系分组、串行执行；不得未经检查直接将全量设为 -n 96。
  - 必要时安装并配置 pytest-xdist，使用独立临时目录及测试资源；并行测试 worker
    不等于多 Agent，本条不扩展为创建额外 Agent 的授权。
  - 并发失败须排查真实回归、资源冲突或时序问题；必要时定向串行复现，
    不通过跳过测试、放宽断言或静默重跑成功来掩盖失败。记录执行范围、worker 数、
    并行/串行分组、失败原因及最终结果，保留完整验收覆盖。
  - 已运行的回归不因优化并行而擅自中止或重复启动；先跟进原进程至终态，
    后续测试批次再应用并行方案。运行期间不修改该批次的生产代码或测试。
  - 有前置依赖的测试须等待前置步骤成功后再调度；独立测试组可以同时推进。
    汇总时确认所有测试进程已退出并记录退出码，不以部分输出或尚在运行的批次
    宣称全量通过；不遗漏串行组或因并发调度而减少覆盖。


七、本阶段完成条件与交付

- 启动→普通输入/编辑→Working 与持续耗时→回复和工具结果→继续输入→
  取消→退出的基本闭环稳定可用；布局、文字和状态提示在高频场景下
  与 Codex 的交互设计足够接近，无明显遮挡、残影、错误计时或输入区错乱，
  并有相称的行为/渲染/PTY 验证；已有审批入口单独验证不会错误授权或卡住输入。
- 已知 P0/P1 和常用流程中可复现、影响使用的 CLI bug 已修复验证；重要剩余问题
  如实列出。不要求证明“绝对没有 bug”，也不以功能清单或像素级 Codex 一致为门槛。
- 斜杠命令、命令菜单、发现/补全扩建、完整主题复刻及罕见终端特性均不是完成条件；
